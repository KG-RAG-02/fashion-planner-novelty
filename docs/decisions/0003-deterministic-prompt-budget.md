# 0003 · 잘라내기 대신 결정적 프롬프트 예산

- 상태: 채택
- 범위: 텍스트 LLM 입력

## 맥락

신뢰할 수 없는 기획 데이터는 24,000자 상한으로 직렬화되어 프롬프트에 들어간다. 상한을 넘으면 직렬화기가 데이터를 6,000자 미리보기로 바꿨고, 미리보기에는 쓸 수 있는 근거 ID가 없었다. 그 결과 유료 호출 뒤 모든 응답이 검증에서 떨어졌다. [T-TEXT-01](../troubleshooting.md#t-text-01) 참고.

## 결정

- 직렬화기가 데이터를 접기 전에 `domain/prompt_budget.py`가 정해진 단계로 데이터를 줄이고, 단계마다 직렬화한 크기를 다시 잰다.
  - T1: 중복된 한계 문장을 뺀다.
  - T2: 참조 토큰과 숫자만 다른 문장을 묶는다.
  - T3: 구조를 압축한다.
  - T4: 근거 ID를 짧은 별칭으로 바꾸고 응답에서 되돌린다.
  - T5: 내용을 줄인다(손실 있음).
- 상한 안에 들면 바로 멈춘다.
- 그래도 넘으면 모델을 호출하지 않고 `TEXT_INPUT_OVER_BUDGET`으로 규칙 기반 Draft를 쓴다.
- 축약한 실행은 `generation_metadata.prompt_reduction`에 한 일을 적는다. T5가 뺀 것이 있으면 Draft의 한계 문장에 밝힌다.

## 결과

- 상한 아래 요청은 바이트 단위로 바뀌지 않는다.
- 검증할 수 없는 데이터로는 유료 호출을 하지 않는다.
- 별칭 복원은 자유 문장에서도 안전해야 한다. [T-TEXT-02](../troubleshooting.md#t-text-02) 참고.

## 검토한 대안

| 대안 | 택하지 않은 이유 |
|---|---|
| 상한을 올림 | 절벽을 옮길 뿐 없애지 못하고, 모든 호출이 커진다 |
| 글자 수로 잘라냄 | JSON 값 중간을 자르고, 재고 상품 전체 같은 절을 조용히 빼먹는다 |
| 모델에게 입력 요약을 시킴 | 근거와 대조할 수 없는 유료 호출이 하나 더 생긴다 |
