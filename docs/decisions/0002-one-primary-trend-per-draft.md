# 0002 · Draft마다 주 트렌드 하나를 규칙으로 고른다

- 상태: 채택
- 범위: 규칙 기반 Draft, 텍스트 LLM 입력, 이미지 사양

## 맥락

트렌드 결과에는 보통 트렌드가 여러 개 들어 있다. 첫 생성기는 쓸 수 있는 모든 트렌드의 속성을 합쳤다. 그래서 Draft 하나가 패턴은 한 트렌드에서, 색은 다른 트렌드에서 가져오고, 기획서는 또 다른 트렌드를 보여 주는 일이 생겼다. [T-PLAN-01](../troubleshooting.md#t-plan-01) 참고.

## 결정

- 쓸 수 있는 후보 중에서 주 트렌드 하나를 고른다. 쓸 수 있는 후보는 이름과 근거가 있고, 요청한 시즌·카테고리·시장·채널과 어긋나지 않는 트렌드다.
- 고르는 순서는 다음과 같다.
  1. 근거가 연결된 디자인 속성이 가장 많은 것
  2. 근거 ID가 가장 많은 것(후보, 설명, 속성 합계)
  3. 먼저 입력된 것
- 규칙 기반 Draft, 텍스트 LLM 입력, 그리고 그에 따른 이미지 사양은 이 트렌드만 쓴다.
- `draft.trend_basis`에 선택을 기록한다: style ID, 이름, 규칙 이름, 근거 ID, 디자인 속성, 검토한 후보 수. 쓸 수 있는 트렌드가 없으면 `null`이다.
- 선택은 코드가 하고 모델은 하지 않는다.

## 결과

- Draft는 트렌드 하나에 관한 것이고, 그것이 무엇인지 밝힌다. 다른 서비스가 같은 트렌드를 나란히 보여 줄 수 있다.
- 텍스트 LLM 입력이 크게 줄었다. 기록된 요청을 다시 돌려 보니 가장 큰 입력이 26,756자에서 16,795자로 줄었다.
- 여러 트렌드를 일부러 섞는 기획은 범위 밖이다. 다른 트렌드를 원하면 호출하는 쪽이 더 좁은 트렌드 결과를 보내야 한다.

## 검토한 대안

| 대안 | 택하지 않은 이유 |
|---|---|
| 모델이 고르게 함 | 재현할 수 없고, 근거와 대조해 확인할 수 없다 |
| 속성을 계속 합침 | 어느 트렌드와도 맞지 않는 일관성 없는 프로필이 나온다 |
| 결과 전체에서 가장 많이 인용된 트렌드 | 인용 수는 상품의 디자인 근거보다 긴 기사에 유리하다 |
