# 결정적 콘셉트 초안 생성 평가 계획

- 상태: 평가 시나리오 제안 · 미실행
- 범위: `generate_concept_draft` 내부 초안 구성과 `validate_concept_draft`
- 측정 결과: 없음

이 문서는 Notion의 Experiments & Evaluation 원칙에 맞춰 시나리오와 기대 동작만 정의합니다. 실제 평가 결과는 합성 또는 사용 승인 입력을 준비하고 코드를 특정 커밋으로 고정한 뒤 기록합니다. 현재 문서에 정확도나 품질 수치를 기입하지 않습니다.

## 시나리오와 기대 동작

| 시나리오 | 입력 조건 | 기대 동작 |
| --- | --- | --- |
| 정상 입력 | 요청·트렌드·재고가 같은 request/schema 버전이고 각 근거 ID가 유효 | 요청 속성, 근거 연결 트렌드 속성, 자사 상품 참조를 구분해 초안에 담고 입력별 상태와 Evidence를 보존 |
| 동일 에이전트의 두 결과 | PlanningRequest와 TrendResult의 `agent_id`가 동일 | 허용. 두 결과의 상태는 각 입력 슬롯에 따로 보존 |
| 트렌드 부분 결과 | `TrendResult.status=partial`, 일부 후보와 제한사항 존재 | 가진 근거는 사용하고 partial 상태·제한을 보존. 자료가 완전한 것처럼 표시하지 않음 |
| 재고 no_results | 조회 자료 없음 | 재고 0으로 만들지 않음. 상태와 조회 확인 질문을 보존 |
| 실제 재고 0 | 재고 레코드에 수량 0, 단위·정의·기준일·Evidence가 명시됨 | 실제 0 수량과 스냅샷 근거를 자사 상품 관계 메모에 보존. 수요나 판매 부진으로 해석하지 않음 |
| 조건 충돌 | 요청과 트렌드/재고 사이 시즌·지역·카테고리·속성 값이 겹치지 않음 | 충돌과 확인 질문을 기록하고 충돌을 임의로 해소한 제안을 만들지 않음 |
| 근거 없는 트렌드 속성 | 후보 속성에 Evidence ID가 없음 | 관찰로 단정하지 않고 검증 대상으로 표시 |
| 모르는 Evidence ID | draft가 입력 컨텍스트에 없는 ID를 참조 | 검증 이슈 `UNKNOWN_EVIDENCE_ID` 반환 |
| 요청에 없는 사용자 속성 | 생성 초안이 임의 값을 `user_requested`로 표시 | 검증 이슈 `UNREQUESTED_VALUE_MARKED_AS_USER_INPUT` 반환 |
| 고객/가격 정보 누락 | 요청에 관련 조건이 없거나 missing_fields에 기록 | 고객을 unknown으로 남기고 검증 질문 제시. 가격·원가·수요를 만들지 않음 |
| 요청 조건과 맞지 않는 트렌드 후보 | 후보의 시즌/카테고리/지역/채널이 요청과 불일치 | 해당 후보는 비교 근거로 사용하지 않고 불일치와 확인 질문을 보존 |
| 트렌드와 자사 상품의 같은 속성·같은 값 | 각 값에 Evidence ID가 있고 상품의 주요 조건이 요청과 맞음 | 두 출처에서 값이 관찰됐다고 기록하고, 이를 새 상품 기회로 해석할지는 MD 질문으로 남김 |
| 트렌드와 자사 상품의 같은 속성·다른 값 | 각 값에 Evidence ID가 있음 | 값 차이만 관찰로 기록. 우위, 차별화, 고객 선호라고 단정하지 않음 |
| 자사 상품 속성 자료 없음 | 검색 결과에 해당 속성이 없고 카탈로그 완전성 미정 | 실제 상품에 그 속성이 없다고 표현하지 않고, 비교 불가 제한을 남김 |
| 한 입력 상태가 error/no_results | 해당 결과 payload에 필드가 포함되어 있어도 상태가 실패/결과 없음 | 그 입력의 후보를 생성 근거로 쓰지 않고 상태·제한·확인 질문을 보존 |

## 평가 실행 시 기록할 내용

- 입력 데이터의 합성/승인 상태와 데이터 버전
- 코드 커밋과 실행 환경
- 각 시나리오의 실제 결과, 예상과 다른 동작, 후속 수정
- Evidence 출처·사용 권한 확인 상태
- 생성된 제안과 가설이 사실 주장으로 오인될 수 있는 표현
- 입력 partial/no_results/error와 실제 값 0의 보존 여부

대화형 모델이나 품질 점수를 추가하려면 평가 기준·검토자를 먼저 합의합니다. 테스트 데이터가 확보되기 전까지 생성 품질 수치나 시장 성과를 주장하지 않습니다.

## RAG-grounded LLM 생성기를 도입할 때

현재 계획에는 모델 제공자나 모델 SDK가 정해져 있지 않습니다. 도입 승인 후 `ConceptGenerator` 포트 구현을 추가하고 다음 항목을 기록합니다.

- provider/model/version, prompt template version, generation 설정
- 사용한 Query & Trend Agent Evidence와 데이터 버전
- 입력 Evidence ID 외의 인용을 생성했는지 여부
- 주장별 Evidence ID가 실제 입력에 존재하고 그 주장을 뒷받침하는지 사람 검토
- 사용자 요청과 근거 관찰을 분리했는지, 근거 없는 고객/수요/가격 가정을 만들지 않았는지
- 부분 결과, 충돌, 누락, 모델 장애 때 입력 제한과 fallback 상태를 보존했는지

모델이 응답에 적은 출처나 Evidence ID 자체는 검증된 근거로 간주하지 않습니다. 실제 source locator와 사용 권한은 upstream Evidence에 있어야 하며, 모델 출력 ID는 입력 allowlist와 대조합니다. 승인된 민감도 검토 없이 원문이나 개인정보를 모델에 보내지 않습니다.
