# 프롬프트 안전과 모델 경계

텍스트 LLM과 이미지 모델에 들어가는 데이터는 모두 외부에서 왔다. 사용자 질문, 트렌드 설명, 재고 메모에 지시문처럼 보이는 문장이 들어 있을 수 있다. 이 문서는 서비스가 그런 입력을 어떻게 다루는지, 그리고 무엇을 보장하지 않는지 적는다.

## 텍스트 LLM

- **데이터는 데이터로만 넣는다.** 기획 데이터는 JSON으로 직렬화해 사용자 템플릿의 이름 있는 자리표시자 하나에 넣는다. JSON 이스케이프 때문에 줄바꿈·따옴표·제어 문자가 새 프롬프트 구역을 만들지 못한다. 시스템 템플릿은 그 데이터를 신뢰할 수 없는 데이터로 다루라고 지시한다.
- **길이를 제한한다.** 문자열 하나는 2,000자, 배열·객체는 항목 100개, 깊이는 8단계까지만 넣는다. 전체는 24,000자 상한이 있고, 넘으면 [결정적 프롬프트 예산](decisions/0003-deterministic-prompt-budget.md)으로 줄이거나 호출하지 않는다.
- **도구가 없다.** Responses API 요청에 `tools: []`, `store: false`를 보낸다. 모델은 파일·네트워크·다른 서비스에 접근할 수 없다.
- **출력은 엄격하게 검증한다.**
  - `strict` JSON 스키마로 구조를 강제한다.
  - 응답이 인용한 근거 ID가 이 요청의 입력에 있는지 확인한다.
  - 필수 프로필 필드가 채워졌는지 확인한다.
  - category와 season은 요청 값과 같아야 한다.
  - 성별을 요청하지 않았으면 `unknown` 제안값만 받는다.
  - 하나라도 어긋나면 응답 전체를 버리고 규칙 기반 Draft를 쓴다(`TEXT_OUTPUT_INVALID`).
- **오류는 안전한 코드로만 남긴다.** 제공자 오류 본문과 인증 정보는 로그와 응답에 넣지 않는다.

## 이미지 모델

- 이미지 프롬프트는 Draft의 상품 프로필에서 출처가 `user_requested`, `evidence_observation`, `proposal`인 값과 디테일만 골라 만든 JSON 사양으로 만든다. 사용자 질문 원문이나 트렌드 설명 원문은 넣지 않는다.
- 착장 편집에는 생성된 상품 이미지와, 있으면 재고 상품 사진을 입력 이미지로 넣는다. 재고 사진의 이용 조건은 [data.md](data.md)를 본다.
- 이미지 안에 문구·로고·워터마크를 만들지 말라고 지시한다. 다만 모델이 지시를 항상 지킨다는 보장은 없다.

## 보장하지 않는 것

- 프롬프트 구성은 다층 방어일 뿐이다. 데이터 안의 문장이 모델의 출력에 영향을 줄 수 있다.
- 근거 ID 검사는 인용한 ID가 이 요청에 있다는 것만 증명한다. 출처가 그 주장을 의미상 뒷받침하는지, 출처가 정확하거나 이용 권한이 있는지는 판단하지 않는다.
- 민감한 데이터를 외부 모델로 보내도 되는지는 운영자가 판단해야 한다. 이 서비스는 `LLM_API_KEY`가 있으면 위 데이터를 보낸다.
